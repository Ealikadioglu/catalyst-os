# Spec Lifecycle Board

> **When to invoke:** After ANY spec lifecycle transition (catalyze / forge / audit / seal / archive), and whenever the roadmap or dashboard must reflect reality.
> **Invoked by:** `spec-shaping`, `build-orchestration`, `spec-validation`, `spec-approval`, `spec-archival`, `project-sync`, `project-initialization`, and the `/plan-project` command.

This skill is the **single source of truth** for the spec lifecycle. The board itself (`roadmap.md` + `dashboard.html`) is generated by a **script, not by you**. Your entire job on a transition is one shell command.

## The Lifecycle

```
Backlog → Planned → In Progress → Audited → Done (sealed)
```

| State | Meaning | Detected from disk by | Next command |
|-------|---------|-----------------------|--------------|
| 🗂️ **Backlog** | Idea, not yet catalyzed | Roadmap entry only, no spec folder | `!/catalyze-spec "{seed prompt}"` |
| 📋 **Planned** | Catalyzed, ready to build | `spec.md` exists, no `tasks.md` | `!/forge-spec @{slug}` |
| 🔨 **In Progress** | Being built (TDD) | `tasks.md` exists, no passing `validation.md` | `!/audit-spec @{slug}` |
| 🔬 **Audited** | Validated, awaiting seal | `validation.md` contains `Overall Status: PASS` | `!/seal-spec @{slug}` |
| ✅ **Done** | Sealed / archived | Folder is in `.catalyst/specs/completed/` | (none) |

`▶ Next Up` = the spec closest to Done (Audited → In Progress → Planned → top of Backlog).

A Backlog entry graduates automatically the moment a spec folder whose slug ends in its `Catalyze as` slug appears on disk. A slugless entry graduates when a spec with the same title appears, or when its title is marked ✅ (it is then recorded in Done). Backlog `### N.` numbers are permanent IDs and are never renumbered; free text between `---` separators and the Backlog intro are kept. Done rows are merged with disk, never dropped.

## Update the Board — the only step

```bash
node .catalyst/bin/board.js --by "/{command-that-just-ran}"
```

That command:
- Scans `.catalyst/specs/` and classifies every spec with the table above
- Rewrites the lifecycle sections of `.catalyst/main/roadmap.md` (Next Up, Planned, In Progress, Audited, Done) — **preserving Backlog, Vision, and every other section verbatim**
- Regenerates `.catalyst/dashboard.html` from the template plus the raw `.catalyst/main` docs
- Refreshes `.catalyst/main/roadmap.json` when the project opted in with `/roadmap-json`: one flat `specs[]` list with `status`, `requires`, and `ready` for orchestrators. Never edit it by hand
- Prints a 4-line summary. Paste that summary into your report; do nothing else.

If it prints `Board: skipped — no roadmap.md`, the project has never been planned. Say so in one line and move on. Do **not** create a roadmap on a transition — only `/plan-project` and `/catalyze-project` pass `--init`.

## What you must NOT do

- Do **not** read `temp-dashboard.html`. Do **not** write `dashboard.html`. Do **not** build a `DATA` object. The script does all of it deterministically at zero token cost.
- Do **not** hand-edit `roadmap.md` on a transition. The script derives lifecycle state from disk; edits would be overwritten.
- Do **not** re-plan or reorder the Backlog on a transition — that is `/plan-project`'s job, and it is the one place a model edits `roadmap.md` (Backlog and Vision sections only), followed by the same script call.

> Why this is strict: before this script existed, every lifecycle command re-read a 30 KB template plus all of `.catalyst/main` and re-emitted a 30 KB HTML file. That was the single largest source of token spend in the framework, on every command, forever.
